# 🧠 Шаблон постановки задачи для генерации логики (engine tasks)

> Используется для задач, где есть текст и БД, и нужно связать данные с шаблонами Word.
> Архитектура проекта уже существует и **не должна изменяться**.

---

## 🔹 Контекст проекта

Проект: Java

Архитектура:

* `domain/model`
* `domain/repository`
* `domain/service`
* `infrastructure/db/repository`
* `domain/util`
* `word/blocks/text/TextPlaceholderService`

Технические правила:

* Доступ к БД: `DbUtils + RowMapper`
* Репозитории: `Jdbc*Repository`
* Сервисы: прокси-стиль (как `AsfService`)
* `id` везде `int`
* **без Optional**
* **без Long**
* без изменения архитектуры
* без новых паттернов
* без изменения слоёв
* форматирование текста только через `domain.util`
* логика связывания сущностей только в `TextPlaceholderService`

## 🔹 Что нужно сделать

1. Создать `domain/model/<Entity>`
2. Создать `domain/repository/<Entity>Repository`
3. Создать `infrastructure/db/repository/Jdbc<Entity>Repository`

    * стиль: `DbUtils + RowMapper`
4. Создать `domain/service/<Entity>Service`

    * стиль как `AsfService`
5. Создать `domain/util/<Entity>TextFormatter`

    * только логика формирования текста
6. Придумать плейсхолдер(ы) для шаблона

    * пример: `${ENTITY_TEXT}`
7. Подключить в `TextPlaceholderService`

    * показать **конкретные правки в коде**
8. Заменить хардкод на плейсхолдеры
9. (если нужно) дать SQL для заполнения таблицы

---

## 🔹 Ограничения

* ❌ не менять архитектуру
* ❌ не вводить Optional
* ❌ не вводить Long
* ❌ не менять стиль сервисов
* ❌ не менять DbUtils
* ❌ не добавлять DTO
* ❌ не делать связи в сервисах
* ❌ не переносить бизнес-логику в repository

---

## 🔹 Где должна быть логика

| Слой                   | Что там              |
| ---------------------- | -------------------- |
| repository             | только SQL           |
| service                | только прокси-методы |
| domain.util            | формирование текста  |
| TextPlaceholderService | связывание данных    |
| word                   | шаблоны              |
